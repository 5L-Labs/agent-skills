# Run log — 2026-11 security manifest audit (185 skills)

Environment-specific notes from the first full Stage-1 run. These are lessons
about this machine and its billing, not rules of the skill. They were moved here
from the skill body because the skill's rules must hold on any machine.

## Model-failure matrix (observed 2026-11)

| Setup | Result | Lesson |
|---|---|---|
| qwen3.8-27b local, 10 tasks | context overflow / gateway interruption, 0 files | small models cannot hold a full review batch |
| qwen/qwen4-max:free, 10-way fan-out | Nous Portal 429 fair-share, 0 files | free tier still has account-level concurrency limits |
| moonshotai/kimi-k3.1-pro, 3-way | 54 skills verified, then 402 out of credits | paid model works until billing stops; per-skill checkpoints saved the work |
| tencent/hy4-flash:free, 3-way | all remaining work completed | safe default in this environment |

Raw HTTP calls with the auth.json token failed 401; the kilocode key returned 401
INVALID_TOKEN; openrouter returned 402 no credits. The gateway CLI path
(`hermes chat -m ...`) worked when raw API calls did not. Smoke-test before a
large fan-out: `hermes chat -q 'Reply OK' -Q -m <model> --max-turns 1`.

## Dispatch rules that worked here

- Pin the child model in config: `hermes config set delegation.model <model>` and
  `delegation.provider`. Per-task `model`/`provider` passed to `delegate_task` are
  ignored when config pins one.
- Keep `delegation.max_concurrent_children` at 3 and send at most 3 tasks per call.
  The tool rejects larger calls, and a 10-way fan-out hit Nous Portal 429 fair-share.
- A free model at 3-way concurrency is the safe default; paid models can die
  mid-run with 402. Per-skill checkpointing makes that survivable.
- In delegated sessions `execute_code` approval prompts block. Put "use
  `patch`/`write_file`, never `execute_code`" in the briefing.
- Batch files must carry absolute paths; a relative "read shared_context.md"
  resolved to the wrong directory in one child.
- A content-policy refusal can arrive AFTER all files were checkpointed. Verify on
  disk before re-dispatching.
- For the HERMES-1 audit the run used the strongest model and waited or retried on
  capacity errors rather than downgrading.

## Residual state worth knowing

- The first corpus was built at hermes-agent `88a1c1f4` with the pre-review
  generator: 125 of 185 manifests were `wide`, confidence 0.85-0.99 carried
  `method: static`, and the registry entry was hand-typed. Both are superseded by
  the deterministic rules in `SKILL.md` and the stage gate in `validate_corpus.py`.
- A child that has verified a skill on disk still self-reports. Always verify on
  disk before declaring a corpus done.
